EXOKit

Exchange Online and Microsoft 365 administration, in a native Windows app.

  • WinUI 3 on .NET 10
  • Exchange Online PowerShell, in process
  • Microsoft Graph
  • ServiceNow, optional

The sidebar

Every routine Exchange request, one window.

Thirteen sections replace the old WinForms toolkit. Change access, create mailboxes and groups, look things up, and undo removals.

  • Ported from the PowerShell Exchange Admin Toolkit with feature parity.
  • Only one operation runs at a time, and Cancel stops the active command.

Connections

Exchange first, then Graph.

EXOKit hosts a real Exchange Online PowerShell session and a Microsoft Graph client inside the app. Graph must sign in to the same tenant as Exchange.

  1. 1Exchange OnlineEmbedded PowerShell 7.6.6 runspace
  2. 2Microsoft GraphMSAL sign-in, same tenant
  • Modules are checked and updated before sign-in starts.
  • MFA and Conditional Access apply as usual. Nothing is bypassed.

Mailboxes

Grant access. Then prove it.

Full Access, Send As and Send on Behalf, for many users and mailboxes in one batch. Each change is read back until Exchange confirms it.

Read-backevery 2 s, up to 15 readsverified on read 4
0 s30 s
  • A state it cannot read stays unconfirmed. It never counts as success.

Ticket notes

The ticket notes write themselves.

Every batch ends with a For IT Ticket block. Copy it in one click, or close the ServiceNow ticket from inside EXOKit.

  • Only fully verified batches are offered for closure. Partial, cancelled and unconfirmed results are not.
  • ServiceNow credentials come from Azure Key Vault.

Reporting

Who has access? One report.

Group membership and owners, or mailbox permissions, for any target. Export to CSV for the ticket or the audit.

  • The banner tells complete, empty, partial, failed and cancelled results apart.
  • Exports are protected against spreadsheet formula injection.

Snapshots

Every removal leaves a way back.

Before EXOKit removes a permission or role, it saves the current state. Restore puts missing rights back and verifies each one.

  1. 1Snapshot savedtenant-bound, before any change
  2. 2Removed and verifieda failed snapshot blocks this step
  3. 3Restored and verifiedmissing rights only
  • Every Exchange command has a five-minute timeout.
